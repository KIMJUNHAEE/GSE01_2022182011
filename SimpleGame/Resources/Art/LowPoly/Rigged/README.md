# STAR DRIFTER — NPC 리깅 및 엘리시움 몹 7종

2026-10-20. 기존 로우폴리 팩에 리깅·스키닝·키프레임 애니메이션을 추가한 모델링 결과물이다. 게임 코드, 빌드, 스폰 데이터와 충돌 시스템에는 적용하지 않았다.

**2.1 수정:** 4족 몹 3종의 뒷다리를 발목이 들린 동물형 구조로 교체했다. 허벅지·정강이·발허리·발의 4개 부위를 독립적으로 움직인다. 무릎은 앞쪽으로, 비절은 뒤쪽으로 꺾이며 발바닥 전체를 길게 대던 신발형 발을 낮은 발바닥과 세 발가락으로 바꿨다. 해당 몹의 30개 액션을 다시 베이크했으며 모델 ID·인덱스·클립 이름은 유지했다.

## 엘리시움 몹 7종

현재 주력 행성의 AI 통제와 붕괴 이후 개척 시설에 맞춘 지상 기계형 디자인이다. 아래 이름과 역할은 모델 시안이며 게임의 몬스터 스폰·능력치·전투 규칙을 확정하는 데이터가 아니다.

| 인덱스 | 모델 ID | 이름 | 이동 방식과 형태 |
|---|---|---|---|
| 0 | `MOB_ELY_000_ScrapRunner` | 고철 수거 기계 | 2족, 작은 체구·녹슨 외장·단안 센서 |
| 1 | `MOB_ELY_001_PatrolSentinel` | 통제 순찰 기계 | 2족, 청회색 외장·가로 감시창 |
| 2 | `MOB_ELY_002_RiotEnforcer` | 중장갑 진압 기계 | 2족, 넓은 어깨·진압 방패·황색 경고등 |
| 3 | `MOB_ELY_003_OracleWarden` | ORACLE 수호 기계 | 2족, 큰 체구·발광 코어·중계 안테나 |
| 4 | `MOB_ELY_004_TraceHound` | 추적 사냥 기계 | 4족, 긴 주둥이·꼬리·낮은 자세 |
| 5 | `MOB_ELY_005_CargoMite` | 화물 회수 기계 | 4족, 낮고 넓은 몸체·화물 등판 |
| 6 | `MOB_ELY_006_SiegeCrawler` | 사족 경계 기계 | 4족, 넓은 지지 폭·장갑·상부 감시 포탑 |

각 몹은 하나의 메시와 하나의 리그로 구성된다. 2족은 20본, 수정된 4족은 22본이다. 4족의 뒷다리는 `hind_upper`(허벅지) → `hind_lower`(정강이) → `hind_metatarsal`(비절에서 발까지의 발허리) → `hind_foot`(발) 순서다. 새 본은 `hind_metatarsal.L`과 `hind_metatarsal.R`이며, 기존 `hind_foot` 이름은 발 본으로 유지했다. 본 번호는 가져온 스킨의 joint 배열 또는 본 이름으로 연결하며 20개로 고정하지 않는다.

기계 관절은 구형 연결부와 겹치는 외장으로 만들고 부위별로 강체에 가까운 스킨 웨이트를 사용했다. 지상 몹이므로 7종 모두 걷기·달리기·점프·방향 전환을 가진다. 4족 뒷발은 접지 중에도 비절이 들려 있으며, 발을 뗄 때 비절과 발허리를 함께 접고 밀어낼 때 펴도록 조정했다.

## NPC 파트 재사용

기존의 슬롯과 파트 번호를 유지했다. 몸형 2, 머리 5, 상의 6, 하의 3, 신발 3, 액세서리 5, 모자 2개가 공용 `SK_NPC_Common` 리그를 사용한다. 3등신 체형과 발밑 원점도 유지했다. 팔꿈치가 구부러질 수 있도록 긴 팔·소매에 중간 분할을 추가하고, 어깨·팔꿈치·무릎·몸통에 웨이트를 넣었다. 손가락별 뼈나 얼굴 표정 리그는 포함하지 않는다.

`Data/npc_rig_bindings.json`에 기존 NPC 16개 각각의 파트 인덱스·색상 인덱스·공용 리그 연결을 저장했다. 모자·헬멧을 쓸 때 머리를 `-1`로 선택하는 규칙도 유지한다. 모든 파트는 같은 루트 아래에 위치·회전 0, 배율 1로 조립한다.

개별 NPC 파트 GLB에는 독립적으로 열 수 있도록 **동일한 공용 뼈대와 10개 클립을 각각 포함**했다. 게임에 적용할 때는 이 뼈대를 26개 동시에 생성하지 말고, 본 이름으로 스킨을 연결해 NPC당 공용 리그 하나를 재사용한다. 메시도 파트별 원본을 재사용한다. `NPC_001_Sera_Example.glb`는 조립·색상 적용을 보여 주는 예시이며 새로운 파트 인덱스가 아니다.

Blender 원본의 `02_All_NPC_Rigged_Presets` 장면에서는 16개 조합이 같은 메시 데이터와 공용 스켈레톤 데이터를 재사용한다. 각 인스턴스의 포즈와 위치는 독립적이다.

## 키프레임 애니메이션

8개 리그 각각 아래 10개 액션을 가진다. 총 80개의 실제 액션이며, Blender에서는 `리그명__클립명`으로 구분한다. GLB에서는 클립명으로 내보냈다.

| 클립 | 용도 | 반복 |
|---|---|---|
| `Idle` | 서 있는 대기 자세 | 반복 |
| `Walk` | 걷기 | 반복 |
| `Run` | 달리기 | 반복 |
| `Jump` | 준비 자세 → 도약 → 체공 → 착지 → 회복 | 단발 |
| `Turn_L_45`, `Turn_R_45` | 좌우 45° 전환 | 단발 |
| `Turn_L_90`, `Turn_R_90` | 좌우 90° 전환 | 단발 |
| `Turn_L_180`, `Turn_R_180` | 좌우 180° 전환 | 단발 |

30fps 기준으로 매 프레임 위치와 쿼터니언 회전을 키프레임으로 베이크했다. 제작 과정에서 발 목표와 다리 길이를 계산했지만, 최종 파일은 런타임 IK·드라이버·물리 시뮬레이션 없이 재생 가능한 일반 키프레임이다. 움직이는 채널은 선형 보간이며 회전은 쿼터니언이다. GLB 내보내기에서 값이 변하지 않는 채널만 고정 STEP으로 최적화될 수 있다.

2족 걷기는 좌우 발을 반 주기씩 어긋나게 딛고 반대 팔을 흔든다. 달리기는 팔꿈치를 더 굽히고 무게중심을 낮추며 두 발이 동시에 떠 있는 구간을 포함한다. NPC와 각 기계의 체격에 맞춰 액션 길이를 달리했다.

4족 걷기는 뒷왼발 → 앞오른발 → 뒷오른발 → 앞왼발의 4박 순서를 사용하고 약 77%의 접지 구간으로 세 발 지지를 유지한다. 달리기는 앞왼발·뒷오른발, 앞오른발·뒷왼발의 대각선 짝을 사용한다. 추적 사냥 기계는 짧은 체공 구간을 가지며, 무거운 화물 회수 기계와 사족 경계 기계는 지지 시간이 긴 트로트로 움직인다. 전·후 다리의 관절 굽힘 방향을 구분했다.

방향 전환은 몸체만 돌리지 않고 발을 들어 새 방향에 놓는다. 2족은 좌우 발을 번갈아 옮기고 4족은 작은 15° 회전 단계마다 대각선 다리 짝을 옮긴다. 큰 몸체의 4족 전환은 여러 번 발을 디디므로 2족보다 길다.

## 이동·보간 적용 정보

`Data/animation_clips.json`에 리그별 클립 이름, 프레임 범위, 재생 시간, 반복 여부, 회전 각도, 보폭과 권장 이동 속도가 있다. `Data/gait_profiles.json`에는 각 발의 위상과 보행 패턴이 있다. 발의 위상은 전체 주기에 더하는 오프셋이며, `fract(전체 위상 + 발 오프셋)`이 접지 비율보다 작을 때 접지 구간이다.

걷기·달리기는 **제자리 동작**이다. 엔진에서 캐릭터를 `suggested_speed_mps`로 전진시키면 접지 중인 발목의 전후 위치가 월드 기준으로 고정된다. 이동 속도를 바꿀 때는 액션 재생률도 같은 비율로 조정한다. `stance_travel_m`은 발이 접지 중 뒤로 이동하는 거리, `stride_m`은 한 주기 동안 캐릭터가 전진하는 거리다. 두 값은 접지 비율 때문에 다르다.

점프는 `root` 본에 수직 이동이 포함된다. 게임의 점프 물리로 높이를 처리할 경우 애니메이션의 루트 높이를 추출하거나 제거해 이중 이동을 피한다. 점프는 준비·착지까지 포함한 단발 동작이며 반복 클립이 아니다.

방향 전환은 `root` 본에 실제 회전이 포함된다. Blender Z축 기준 `L`은 양의 각도, `R`은 음의 각도다. GLB에서는 같은 동작이 Y축 회전으로 변환된다. 루트 회전을 캐릭터 방향으로 누적·추출하고 다음 대기/이동 동작에 연결해야 방향이 원래대로 돌아가지 않는다. 작은 전환은 45°, 큰 전환은 90°·180° 클립을 기준으로 선택한다.

전환 시작·끝의 공통 접지 자세에서 짧게 교차 보간할 수 있다. 회전 각도별로 발을 디디는 횟수와 길이가 다르므로 클립 중간을 단순히 같은 정규화 시간으로 섞으면 접지가 어긋날 수 있다. 걷기↔달리기도 `gait_profiles`의 발 위상을 맞춰 보간한다. 실제 상태 전환 제어는 다음 게임 적용 작업의 범위다.

미터 단위이며 Blender는 Z 위쪽/-Y 정면, GLB는 Y 위쪽/+Z 정면이다. 기존 환경 모델은 상위 `LowPoly/Meshes`를 계속 사용한다. 이 폴더의 GLB를 리깅 버전으로 사용하며 상위의 정적 NPC GLB와 혼동하지 않는다.

## Blender에서 확인

- `00_Rigged_Mob_Lineup`: NPC와 몹 전체 미리보기.
- `02_All_NPC_Rigged_Presets`: 기존 NPC 16개 조합, 공용 걷기 액션 연결.
- `90_NPC_RigParts`: 원점에 겹쳐 있는 NPC 공용 파트와 공용 리그. 파트를 단독 표시해 편집한다.
- `91_Mob_RigSources`: 몹 7종의 원본 메시와 리그. 원하는 리그·메시를 단독 표시한다.
- `92_NPC_Sera_Export`: 세라 조립 예시.

미리보기 장면은 대기 또는 걷기 액션이 연결되어 있다. 다른 동작은 Armature 선택 후 Action Editor에서 리그명에 맞는 액션을 고르면 된다. 소스 리그의 NLA 트랙은 액션을 보관하기 위해 음소거해 두었으며 여러 클립이 겹쳐 재생되지 않는다.

## 점검 결과와 범위

- 8개 리그의 80개 액션 전 프레임을 검사했다. 반복 끝점, 본 배율, 변형된 발바닥 높이를 확인했다.
- 다리가 닿을 수 없는 목표로 강제 고정되는 구간은 없다. 모든 스킨 정점의 웨이트 합은 1이며, NPC는 최대 2개 본, 기계 몹은 부위별 1개 본의 영향을 받는다.
- 권장 전진 속도를 적용한 접지 프레임의 발목 전후 미끄러짐을 별도로 확인했다.
- 34개 GLB의 본 개수(2족/NPC 20, 4족 22), 스킨 웨이트, 삼각형 인덱스, 10개 애니메이션, 회전값과 반복 연결을 확인했다.
- 세라 조립 예시·2족 수호 기계·4족 추적 기계의 GLB를 비어 있는 Blender에 다시 불러와 10개 액션과 실제 스킨 변형이 유지되는지 확인했다. 결과는 `Data/glb_roundtrip_validation.json`에 있다.
- 실제 포즈와 움직임을 렌더해 확인했다. 상세 결과는 `Data/rig_validation.json`, `motion_validation.json`, `foot_contact_validation.json`, `rigged_glb_validation.json`에 있다.
- 4족 수정본은 비절이 발보다 높은지, 무릎이 비절보다 앞쪽으로 굽혀지는지, 발허리 길이가 일정한지, 관절의 도달 범위를 벗어나지 않는지 전 프레임을 확인했다. 결과는 `Data/quadruped_anatomy_validation.json`에 있다.

게임 엔진에서의 로딩·성능·상태 전환·지형 경사에 따른 발 보정은 아직 적용하지 않았다. 공격·피격·사망 애니메이션, 얼굴 표정, 손가락 리깅, 옷·머리카락 물리, 자동 지형 IK는 이번 요청에 포함하지 않았다.
